# Demo (seed) users audit (2026-10-28)

The demo dataset is **50 synthetic accounts**, marked as synthetic in the auth metadata
(`seed = community-2026-10`, `synthetic = true`) and listed in `seed/manifests/community-2026-10.json`. They are not
real people. They use the e-mail domain `community.agroconnect.local`, a reserved name that can't belong to anyone.
Scripts: `scripts/production/seed-lib.mjs` (data), `seed-community.mjs` (accounts, expert approval, resumes),
`seed-posts.mjs` (8 starter posts), `demo-resume.mjs` (synthetic PDF).

## Changes made today
- The 10 expert names no longer start with "Dr." (e.g. "Sreejith Nambiar"): an unverified doctorate must not be shown.
- Each demo expert gets a synthetic **PDF** resume at `<uid>/1767225600000_cv.pdf`, generated by `demo-resume.mjs`.
  The first line reads "DEMO DOCUMENT - NOT A REAL QUALIFICATION". Unit test `tests/unit/demo-resume.test.mjs` checks
  that it is a valid PDF.
- Expert applications are inserted by the service role with that resume path ("Demo profile (not a real
  qualification)") and approved by the admin session through `approve_expert_application`. An already approved
  application without a valid file is fixed through `_attach_resume`.
- Idempotent: a re-run creates nothing. The script now acts as an account only when something on it needs changing,
  so a re-run doesn't touch passwords.
- The dry run prints per-district totals and each expert's resume status (`ok` / `missing` / `will upload`).
- `--demo-credentials` (staging + `--execute` only) gives one Kannur farmer and one Kannur expert a random password. It
  checks that the sign-in works and writes them to `private/demo-credentials.txt` (git-ignored, mode 0600). It prints
  only the e-mails.
